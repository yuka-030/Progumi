## 1. 共通設計方針

### 1.1. ステータスコード設計
本アプリでは、以下のHTTPステータスコードを標準として使用します。

| コード | 意味 | ユースケース |
| :--- | :--- | :--- |
| **200 OK** | 成功 | `GET` によるデータ取得の成功時、`PUT` の更新成功時 |
| **201 Created** | 生成成功 | `POST` によるユーザー登録、用語追加、履歴保存の成功時 |
| **400 Bad Request**| リクエスト不正 | バリデーションエラー（入力不備）、パスワード一致失敗時 |
| **401 Unauthorized**| 認証エラー | トークンが未送信、または期限切れの場合 |
| **403 Forbidden** | 認可（権限）エラー | 一般会員が管理者のAPI（用語追加・削除）を叩いた場合 |
| **404 Not Found** | 該当なし | 存在しない用語IDを指定した場合 |
| **500 Internal Error**| サーバーエラー | AI API（Gemini等）との通信失敗、DB接続エラー時 |

### 1.2. エラーレスポンス形式の統一
エラー発生時は、フロントエンド側でエラーメッセージをハンドリングしやすいよう、以下の形式（JSON）で統一して返却します。

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "入力されたメールアドレスは既に登録されています。"
  }
}
```

## 2. 認証・認可設計（JWT利用方針）

### 2.1. 認証フロー
1. ユーザーがログイン（`POST /auth/login`）に成功すると、バックエンドは **JWT（JSON Web Token）** を発行します。
2. フロントエンドは、受け取ったトークンをブラウザに保持し、認証が必要なAPIを叩く際に、リクエストヘッダーに含めて送信します。
   * **ヘッダー形式**: `Authorization: Bearer <ここにトークン>`

### 2.2. 権限制御（ロール管理）
JWTのペイロード（中身）に `role`（`member` または `admin`）を含めます。
バックエンドは、管理用APIが叩かれた際、トークン内の `role` が `admin` であるかを検証し、満たさない場合は `403 Forbidden` を返します。

## 3. エンドポイント・リクエスト・レスポンス詳細

### 3.1. 認証API

#### ① 新規ユーザー登録 (サインアップ)
* **URL / メソッド**: `POST /auth/signup`
* **バリデーション**: パスワードは8文字以上必須、メールアドレス形式チェック
* **リクエストボディ**:
  ```json
  {
    "email": "user@example.com",
    "password": "password123",
    "name": "タロウ"
  }
  ```



* **レスポンス (201 Created)**:
```json
  {
  "id": 1,
  "email": "user@example.com",
  "name": "タロウ",
  "role": "member"
}

```
* **レスポンス (200 OK):**;

```json
{
  "access_token": "eyJhbGciOiJIUzI1Ni...",
  "token_type": "bearer",
  "role": "member"

}

```

### 3.2. 用語集API（①UI担当 画面連動）
#### ① 用語一覧・詳細取得
URL / メソッド: GET /words

パラメータ（任意絞り込み）: ?category=IT

* **レスポンス (200 OK)**:

```json
[
  {
    "id": 1,
    "category": "IT",
    "term": "API",
    "explanation": "プログラム同士が情報をやり取りするための仕組み。"
  }
]
#### ② 用語の新規追加（管理者専用・②UI担当画面連動）
URL / メソッド: POST /words

認証: 必要（管理者のみ）

リクエストボディ:

```json
{
  "category": "IT",
  "term": "Docker",
  "explanation": "コンテナと呼ばれる独立した環境を作る技術。"
}

```
レスポンス (201 Created):

```json
{
  "id": 2,
  "category": "IT",
  "term": "Docker",
  "explanation": "コンテナと呼ばれる独立した環境を作る技術。"
}

```
### 3.3. クイズAPI（AI連携）
#### ① 4択クイズの生成・取得
URL / メソッド: GET /quiz/generate

パラメータ（任意）: ?category=IT

※今回はMVP開発のため、AIからのレスポンスをそのままフロントに返却します。（Redisキャッシュの実装は今後の展望とします）

### 3.4. クイズ結果（履歴）API
#### ① クイズ結果の保存
URL / メソッド: POST /quiz/history

認証: 必要（会員・管理者のみ、ゲストはフロント側で制御し送信しない）

リクエストボディ:

```json
{
  "score": 80,
  "total_questions": 5
}
```
レスポンス (201 Created):

```json
{
  "history_id": 101,
  "user_id": 1,
  "score": 80,
  "total_questions": 5,
  "created_at": "2026-06-09T22:00:00"
}
```

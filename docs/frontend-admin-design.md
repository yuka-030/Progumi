# プログミ（Progumi）フロントエンド画面設計書（認証・管理機能特化版）

## 1. 概要
本設計書は、プログミ（Progumi）の認証系画面（ログイン・新規登録）および管理者専用画面（ダッシュボード・用語管理一覧・追加・編集）のフロントエンド実装を円滑に進めるための画面設計書である。バックエンド側の「ER図・テーブル定義・リレーション設計」と完全連動し、データ連携における認識のズレや手戻りを防ぐことを目的とする。

## 6. 各画面の詳細

### 6-1. ログイン画面（`/login`）
* **概要:** ユーザーがアプリにログインするための画面。管理者権限を持つアカウント（ロール：`admin`）でログインした場合は、自動的に管理者ダッシュボード（`/admin`）へ遷移する。
* **表示内容:**
    * **クイズ結果保持アナウンスバナー（サブアクセント `#FFB347`）**
        * **【動的表示仕様】** ブラウザの `sessionStorage` 内にゲスト時のクイズ結果（`guest_quiz_result`）が存在する場合のみ、画面上部に自動で表示する（データがない場合は非表示）。
    * フォームエリア（カード背景 `#FFFFFF`）
        * メールアドレス入力欄（プレースホルダー、バリデーションエラー表示あり）
        * パスワード入力欄（伏字表示、非表示切り替えアイコン付き）
    * ログインボタン（メインアクセント `#7C6FD4`）
    * 外部サービス連携ログイン（Google / GitHub等、実装スキームによる）
    * 画面下部導線：「アカウントをお持ちでない方はこちら（新規登録画面へのリンク）」
* **バリデーション仕様:**
    * メールアドレス：必須入力、メールアドレス形式チェック
    * パスワード：必須入力
* **ゲストクイズ結果の引き継ぎ・削除仕様（成功・失敗のコード分岐条件）【最重要】:**
    * ログイン認証成功後、`sessionStorage` 内に `guest_quiz_result` が存在する場合、単なるコメント記述に留めず、**「実際のAPI呼び出し結果」および「レスポンスの成功判定」に基づく厳格なコードによる条件分岐**を実装すること。
        1. **【STAGE 1: サマリー保存】** `POST /api/quiz/results` へ結果概要（ユーザーID、スコアなど）を送信。通信結果のステータスコードを確認し、**成功判定（HTTP 200/201）が取れた場合のみ**レスポンスから `quiz_result_id` を取得して次へ進む。
        2. **【STAGE 2: 詳細データ保存】** STAGE 1の成功を受けて `POST /api/quiz/result/questions` へ詳細データを送信。同様に**通信の成功判定（HTTP 200/201）をコード上で確認する**。
        3. **【STAGE 3: 成功時のみのセッション削除】** STAGE 1 および STAGE 2 の成否をif文やtry-catch等で評価し、**「すべての保存処理が完全に成功した」と判定された時だけ** `sessionStorage.removeItem("guest_quiz_result")` を実行して一時データを削除する。
    * **【安全対策（例外処理・失敗時の保持）】**
        * いずれかのAPI呼び出しにおいて、ネットワークエラーやサーバーエラー（ステータスコード異常）が発生した場合は、**絶対に `removeItem` を実行せず、手元にデータを残す方針をコードで表現すること**。
        * 保存失敗の分岐に入った際は、画面上に「データ同期に失敗しました」等の適切なエラーを表示し、ユーザーの大切なデータが未保存のまま消失するのを完全に防ぐ。
* **権限:** 未ログインユーザーのみアクセス可能（ログイン済みの場合は自動リダイレクト）。

### 6-2. 新規登録画面（`/register`）
* **概要:** 新規ユーザーがアカウントを作成するための画面（`users` テーブルへのレコード挿入）。
* **表示内容:**
    * **クイズ結果保持アナウンスバナー（サブアクセント `#FFB347`）**
        * **【動的表示仕様】** ログイン画面と同様に、`sessionStorage` 内に `guest_quiz_result` が存在する場合のみ、「今登録すると結果が保存されます」というバナーを自動で表示する。
    * フォームエリア（カード背景 `#FFFFFF`）
        * ユーザー名（ニックネーム）入力欄
        * メールアドレス入力欄
        * パスワード入力欄
        * パスワード（確認用）入力欄
    * アカウント作成ボタン（メインアクセント `#7C6FD4`）
    * 画面下部導線：「既にアカウントをお持ちの方はこちら（ログイン画面へのリンク）」
* **バリデーション仕様:**
    * ユーザー名：必須入力、20文字以内
    * メールアドレス：必須入力、メールアドレス形式チェック、重複チェック（API側と連携）
    * パスワード：必須入力、8文字以上、半角英数字混在
    * パスワード（確認用）：必須入力、パスワード入力欄と一致していること
* **ゲストクイズ結果の引き継ぎ・削除仕様（成功・失敗のコード分岐条件）【最重要】:**
    * アカウント新規作成完了直後、**ログイン画面（6-1）と全く同じ安全仕様（コメント止めを防ぎ、APIレスポンスの成否に基づく分岐によって、完全成功時のみ削除・失敗時は必ずデータを保持する実装）**を適用して引き継ぎを実行する。
* **権限:** 未ログインユーザーのみアクセス可能。

### 6-3. 管理者ダッシュボード（`/admin`）
* **概要:** 管理者がシステム管理機能へアクセスするためのポータル画面。一般画面とは異なり、管理者専用の2カラムレイアウト（サイドバー＋メインエリア）を採用する。
* **表示内容:**
    * システム全体の統計情報のサマリー（総ユーザー数、総登録用語数など）
    * 各管理機能へのショートカットリンクカード
        * 「用語管理（登録・編集・削除）」への遷移カード
* **権限:** 管理者権限（ロール：`admin`）を持つ認証済みユーザーのみアクセス可能。一般ユーザーまたは未認証ユーザーがアクセスした場合は、`/login` に強制リダイレクトする。

### 6-4. 用語管理一覧画面（`/admin/terms`）
* **概要:** `terms` テーブルに登録されているプログラミング用語を一覧で確認し、追加、変更、削除の管理操作を行う画面。
* **表示内容:**
    * 用語管理テーブル
        * 列項目：用語ID、用語名、カテゴリ、最終更新日、操作（編集・削除ボタン）
    * 検索およびフィルタリングエリア（用語名での部分一致検索、カテゴリでの絞り込み）
    * 「新規用語追加」ボタン（メインアクセント `#7C6FD4`、クリックすると `/admin/terms/new` へ遷移）
    * アクションボタン：
        * 各行に「編集」アイコン（クリックすると `/admin/terms/[id]/edit` へ遷移）
        * 各行に「削除」アイコン（クリックすると確認モーダルを表示し、DELETE APIをキック）
* **権限:** 管理者権限を持つユーザーのみアクセス可能。

### 6-5. 用語追加・編集画面（`/admin/terms/new`, `/admin/terms/[id]/edit`）
* **概要:** 新しいプログラミング用語の登録、または既存用語（`terms` テーブル）のタイトル・カテゴリ・説明文などの変更を行う共通フォーム画面。
* **表示内容:**
    * ページタイトル（新規追加時は「用語の新規登録」、編集時は「用語の編集」）
    * 入力フォーム（カード背景 `#FFFFFF`）
        * 用語名入力欄（文字列、必須入力）
        * カテゴリ選択（プルダウンまたはラジオボタン、必須入力）
        * 概要説明テキストエリア（文字列、必須入力、最大200文字など）
        * 詳細解説リッチテキスト/テキストエリア（文字列、必須入力）
    * 操作ボタンエリア：
        * 「保存する」ボタン（メインアクセント `#7C6FD4`、APIを実行して一覧へ戻る）
        * 「キャンセル`」ボタン（入力内容を破棄し、一覧画面 `/admin/terms` へ戻る）
* **バリデーション仕様:**
    * 用語名：必須入力、50文字以内
    * カテゴリ：選択必須
    * 概要説明・詳細解説：必須入力
* **権限:** 管理者権限を持つユーザーのみアクセス可能。

## 7. UI設計方針

### カラーパレット

| 役割 | カラーコード | 用途 |
| :--- | :--- | :--- |
| ベース背景 | `#FFF0F3` | 全体の背景色 |
| メインアクセント | `#7C6FD4` | ボタン・ナビ・見出し |
| サブアクセント | `#FFB347` | 通知・ポイント・強調・一時バナー |
| カード背景 | `#FFFFFF` | カード・モーダル・認証フォーム・管理フォーム |
| テキスト | `#1E1828` | 本文テキスト |

### 共通レイアウト
* **管理者画面用レイアウト:** 左側に固定配置される `AdminSidebar`（メニューリンク一覧）と、上部の `AdminHeader`（管理者アバター・ログアウトボタン）、およびコンテンツを表示するメインスクロールエリア。
* **角丸:** `border-radius` 大きめ（`20px`〜`28px`）。ボタン、カード、入力フォームすべてに適用し、プログミ独自のキャッチーでモダンなトーン＆マナーを統一する。
* **余白:** セクション間、カード内余白を広めに設定する。

### レスポンシブ対応方針
* 管理者画面および認証画面はPC操作専用として割り切る設計とする。

## 9. API連携

### 主要エンドポイント

| 画面 | メソッド | エンドポイント | 備考 |
| :--- | :--- | :--- | :--- |
| ログイン | POST | `/api/auth/login` | 認証トークン/セッション発行 |
